# Release Notes - v1.19.0

**Release Date:** July 2026 (official documentation published August 6, 2026)
**TIBCO Platform Control Plane Version:** 1.19.0
**Platform:** Amazon Elastic Kubernetes Service (EKS)
**Status:** Previous release (mandatory upgrade hop between 1.18.0 and 1.20.0)
**Workshop documentation updated:** September 21, 2026

## Overview

This release documents TIBCO Platform Control Plane 1.19.0 for the EKS workshop. The workshop skipped 1.19.0 when it shipped; it is documented now because the official upgrade assistants only move one minor version at a time, so every 1.18.0 environment must pass through 1.19.0 on the way to 1.20.0.

1.19.0 introduces TESSA (Preview, TIBCO Operated Control Plane US region only), the TIBCO ActiveSpaces capability, the TIBCO Platform Infra MCP Server, PromQL observability cards, a Backstage 1.51.0 based Developer Hub with its own MCP server, and a set of BusinessWorks and Flogo improvements. On the chart side it removes the deprecated network policies, flips the `otel-collector` default, moves Jaeger to the v2 chart line, and fixes the hybrid-proxy Gateway API route.

## What's New in v1.19.0

### TIBCO Control Plane

#### TESSA (Preview)

TIBCO Enterprise Smart System Agent is a natural-language assistant for querying the Control Plane, Data Planes, and capabilities. It is available for TIBCO Operated Control Plane in the US region only and is not available for self-hosted Control Planes, so it does not apply to a self-hosted EKS deployment.

#### TIBCO Platform Infra MCP Server

A read-only Model Context Protocol server that runs on each Data Plane and lets TESSA execute `kubectl` and `helm` diagnostics without giving users cluster access. It is provisioned as a Data Plane capability from the Control Plane UI (chart `tp-dp-infra-mcp-server`). RBAC is created by `dp-configure-namespace` 1.19.10 and later; namespace-scoped by default, cluster-scoped with `--set rbac.infraMcpClusterScoped=true`, extra rules with `--set-json 'rbac.infraMcpExtraRules=[...]'`.

#### TIBCO ActiveSpaces Capability

ActiveSpaces (data grid and vector store, bundled ActiveSpaces 5.2.0) can be provisioned on a Kubernetes Data Plane using the `msg-activespaces-tp` chart. It requires a Message storage class, Data Plane Manager and Capability Manager permissions, and in-product activation.

#### PromQL Observability Cards

PromQL Instant Query and Range Query cards (range window up to 48 hours) let you run custom Prometheus queries inside the Observability dashboard.

#### OAuth Client Registration

Owners and Team Admins can register OAuth2 clients for CI/CD automation from the Control Plane UI.

### Capability Updates

- **BW6 Containers:** auto-discovered applications deployed with Helm or non-Helm mechanisms can be managed from the platform.
- **BW5 Containers:** custom OTel trace tags per activity, new base image (Eclipse Temurin OpenJDK on Red Hat UBI 10 minimal), Group type identification, Shared Resource passwords from AWS Secrets Manager, HashiCorp Vault, or CyberArk, custom adapter upload.
- **ActiveMatrix BusinessWorks 6 (Control Tower):** agent-level RBAC.
- **Flogo:** bulk build cleanup API `DELETE /v1/dp/builds` (`ageInDays`, `mode`, `DoNotDelete` tag), SAP HANA connector, `FLOGO_FLOW_EXECUTE_BRANCHES_CONCURRENTLY`, configurable app-init container resources (`APP_INIT_CPU_REQUEST` 100m, `APP_INIT_MEMORY_REQUEST` 100Mi, `APP_INIT_CPU_LIMIT` 200m, `APP_INIT_MEMORY_LIMIT` 400Mi) in the `flogoprovisioner` chart `config` block.
- **Developer Hub:** Backstage upgraded from 1.41.1 to 1.51.0; new Developer Hub MCP server (`tibco.mcpActions.enabled: true`, endpoint `<DEV_HUB_URL>/api/mcp-actions/v1`).
- **EMS:** public API for provision, update, upgrade, and refresh; server properties editable on the Servers page; Kafka transports shown on the Transports page.

### Changes in Functionality

- Control Plane: none.
- BW5 and Adapters: the application History tab now shows the correct user information.

### Deprecated and Removed

- NGINX Ingress Controller support is removed (same wording as 1.18.0).
- EMS single-form server registration for bare-metal Data Planes is removed; use the interactive YAML editor.

## Supported Platform Versions

Unchanged from 1.18.0: Helm 3.17.0+, PostgreSQL 16, Traefik 3.3.4, Gateway API controllers NGINX Gateway Fabric 2.3.0, Istio 1.28.2, Traefik `traefik-39.0.7`, NetScaler `netscaler-cpx-with-gateway-controller-2.0.0`. Highest certified Kubernetes for the Control Plane cluster: Amazon EKS 1.35.

## EKS-Specific Considerations

- **Simplified DNS with Gateway API:** because the hybrid-proxy route is fixed, both `hybrid-proxy` and `router-operator` HTTPRoutes can use `*.${TP_BASE_DNS_DOMAIN}` on one Gateway when `dnsDomain == dnsTunnelDomain`. Drop the `${CP_INSTANCE_ID}-tunnel` Route 53 record only after confirming tunnel traffic reaches `hybrid-proxy` through the shared hostname.
- **Elasticsearch log export (PCP-23331):** on self-hosted Control Planes, CP service logs can stop reaching Elasticsearch after the 1.18.0 to 1.19.0 upgrade (`document_parsing_exception`, HTTP 400). Workaround: in the `otel-services` configmap set the `elasticsearch/log` exporter `mapping.mode` to `none`, remove `transform/es-bodymap` from the logs pipeline, and restart `cp-otel-services`. Fixed in 1.20.0.
- **Aurora PostgreSQL SSL:** keep `TP_DB_SSL_MODE=require` or `verify-full` when `rds.force_ssl=1` is enforced.
- **Email:** unchanged from 1.18.0; configure SES, SMTP, SendGrid, or Microsoft Graph in the Platform Console, never in Helm values.

## Upgrade Path from v1.18.0

1. Back up Helm values, `session-keys` and `cporch-encryption-secret`, and Aurora PostgreSQL data.
2. Update the `tibco-platform` Helm repository.
3. Remove `global.tibco.networkPolicy.createDeprecatedPolicies` from your values file and set `otel-collector.enabled` explicitly.
4. Upgrade `tibco-cp-base` to 1.19.0 (`helm upgrade ... --version 1.19.0`) or run `scripts/1.19.0/upgrade.sh` from `tp-helm-charts` (requires the release to be `deployed` at `app_version` 1.18.0).
5. Upgrade capability charts to 1.19.0 (`tibco-cp-bw`, `tibco-cp-flogo`, `tibco-cp-devhub`, `tibco-cp-hawk 1.19.23`, `tibco-cp-messaging 1.19.23`).
6. Upgrade Data Plane infrastructure from the Control Plane UI (`dp-configure-namespace` 1.19.10, `dp-core-infrastructure` 1.19.5), then capabilities.
7. Apply the PCP-23331 workaround if CP logs stop arriving in Elasticsearch.
8. Continue to [v1.20.0](./v1.20.0#upgrade-path-from-v1190).

## Known Issues to Review

- **PCP-23331:** CP service logs stop writing to Elasticsearch after upgrading a self-hosted Control Plane from 1.18.0 (workaround above; fixed in 1.20.0).
- **PCP-20976:** BW6 agent auto-switching fails with NGINX ingress and NetScaler gateway controller (fixed in 1.20.0).
- **PCP-20148:** pre-upgrade traces show as red dots after the Jaeger v2 move.
- **PCP-20136:** upgrading a Control Tower Data Plane that uses NGINX ingress can break the observability infrastructure upgrade; delete the legacy `bm-<ingress-class>-{logs,traces,metrics,metrics-export}` ingresses and retry.
- **PCP-19820:** traces and application service metrics do not work with Traefik in Control Tower Data Planes on TIBCO Operated Control Plane.
- **PCP-19687:** cards show wrong data for Data Planes still on the previous release until they are upgraded.
- **MSGDP-199:** EKS default `gp2` storage class does not support EMS shared logs.
- **MSGDP-2341:** ActiveSpaces provisioned after Flogo or BW with the same storage resource omits `storageName`; provision ActiveSpaces first or create a separate storage resource.
- **PLTDX-1459:** Control Plane and Developer Hub on the same cluster with Traefik and identical hostnames return 404.

Review the complete official list: [Official 1.19.0 Known Issues](https://docs.tibco.com/pub/platform-cp/1.19.0/doc/html/Release-Notes/known-issues.htm).
