# Release Notes - v1.20.0

**Release Date:** August 2026 (official documentation published August 31, 2026)
**TIBCO Platform Control Plane Version:** 1.20.0
**Platform:** Amazon Elastic Kubernetes Service (EKS)
**Status:** Previous release
**Workshop documentation updated:** September 21, 2026

## Overview

This release updates the EKS workshop documentation for TIBCO Platform Control Plane 1.20.0. It also catches up on the intermediate 1.19.0 release, which is a mandatory hop when upgrading from 1.18.0 (see [v1.19.0 release notes](./v1.19.0)).

1.20.0 is a small Control Plane release. The headline items are Control Plane rollback support, OTLP exporters with custom headers, dedicated Kubernetes Jobs for Flogo application builds, the Developer Hub MCP Catalog, and MCP Hub (Preview, TIBCO Operated Control Plane only). For self-hosted EKS deployments the most important operator-facing changes are in the `tibco-cp-base` chart: a new `global.tibco.disabledInfraCapabilities` value and a changed `otel-collector` default.

## What's New in v1.20.0

### TIBCO Control Plane

#### Control Plane Rollback

If an upgrade fails, the Control Plane can be rolled back to the version it was upgraded from. With `global.tibco.manageDbSchema: true` (the workshop default) a single `helm rollback <release> <revision> -n <namespace> --wait` reverts both the release and the database schema. With `manageDbSchema: false` you must first run `postgres-helper.bash rollbackDbSchema <chart-version>` from the `tp-helm-charts` database scripts, then run the Helm rollback. TIBCO recommends rolling back the Control Plane before upgrading any Data Planes or capabilities.

#### OTLP Exporter with Custom Headers

OTLP (http and grpc) exporters for logs, metrics, and traces, and OTLP query services, accept custom header key/value pairs. This helps when forwarding telemetry from EKS to SaaS observability backends that require tenant or auth headers.

#### MCP Hub (Preview)

MCP Hub is a central console for Model Context Protocol infrastructure with a built-in MCP Gateway that enforces guardrails and manages plugins for MCP servers, virtual tools, and virtual servers. It is available in TIBCO Operated Control Plane only and is a Preview. The MCP Gateway runtime is a Data Plane capability delivered by the new `tp-mcp-gateway` chart (Full mode uses PostgreSQL and Redis, Lite mode uses SQLite). Self-hosted Control Planes on EKS cannot use MCP Hub in 1.20.0.

### Capability Updates

- **Flogo:** application builds run in dedicated Kubernetes Jobs with their own CPU, memory, queue, and timeout settings (`FLOGO_APP_BUILD_CPU_REQUEST`, `FLOGO_APP_BUILD_CPU_LIMIT`, `FLOGO_APP_BUILD_MEMORY_REQUEST`, `FLOGO_APP_BUILD_MEMORY_LIMIT`, `FLOGO_APP_BUILD_TIMEOUT_SECONDS`, `FLOGO_APP_BUILD_MAX_QUEUED_SECONDS`).
- **Developer Hub:** MCP Catalog registers MCP servers as Backstage API entities (`spec.type: mcp-server`); requires Backstage 1.51.0+ and Advanced navigation mode.
- **BW5 and Adapters (Control Tower):** bulk suspend/resume of process starters, richer Active Processes and Locks tabs.
- **Messaging:** no 1.20.0 EMS or ActiveSpaces charts were published; the latest messaging charts remain 1.19.23. The official compatibility matrix lists EMS 1.19.0 as the latest row.

### Deprecated and Removed

- NGINX Ingress Controller support is removed. TIBCO no longer officially supports or recommends its use with Control Plane and Data Planes (wording unchanged since 1.18.0). On EKS use Traefik (or the optional Gateway API path).

## Chart Changes That Affect EKS Values Files

These come from the `tibco-cp-base` chart source in the official `tp-helm-charts` repository (tag `tibco-cp-base-1.20.0` compared with `tibco-cp-base-1.19.0` and `tibco-cp-base-1.18.0`).

| Value | 1.18.0 | 1.19.0 | 1.20.0 | Action |
|-------|--------|--------|--------|--------|
| `global.tibco.networkPolicy.createDeprecatedPolicies` | `true` | removed | removed | Delete from values files before upgrading to 1.19.0 or later |
| `otel-collector.enabled` (chart default) | `false` | `true` | `false` | Set it explicitly. The 1.20.0 chart disables it so a log server is not a prerequisite for `tibco-cp-base`; enable it only when a log server is configured (audit log, CP Fluent Bit logging) |
| `global.tibco.disabledInfraCapabilities` | n/a | n/a | `[MFTADAPTER]` | New. Capability IDs removed from every Data Plane type's mandatory infra capability list. MFT is off by default; set `[]` to enable all |
| `hybrid-proxy.gatewayRoute` HTTPRoute rules | `/` only (PCP-21362) | `/infra/tunnel` always, `/` only when `dnsDomain != dnsTunnelDomain` | same as 1.19.0 | The 1.18 hostname-separation workaround is no longer needed with simplified DNS |
| Fluent Bit sidecar image tag | 5.0.6 | 5.0.9 | 5.1.0 | Informational |

The `scripts/1.20.0/upgrade.sh` assistant in `tp-helm-charts` performs no value transformations; it only validates the release (must be `deployed` at `app_version` 1.19.0), copies values, and runs `helm upgrade` to chart 1.20.0.

## EKS-Specific Considerations

### Aurora PostgreSQL Parameter Group

The upstream EKS Control Plane workshop for 1.20.0 no longer creates the Aurora cluster parameter group through Crossplane. Create it up front and reference it from the `dp-config-aws` claim:

```bash
aws rds create-db-cluster-parameter-group \
  --db-cluster-parameter-group-name "${CP_RESOURCE_PREFIX}-db-param" \
  --db-parameter-group-family aurora-postgresql16 \
  --description "Custom parameter group for CP RDS cluster"

aws rds modify-db-cluster-parameter-group \
  --db-cluster-parameter-group-name "${CP_RESOURCE_PREFIX}-db-param" \
  --parameters "ParameterName=rds.force_ssl,ParameterValue=1,ApplyMethod=immediate"
```

In the claim values, `dbParameterGroupFamily: "aurora-postgresql16"` and the `groupFamilyParameters` block are replaced by `dbClusterParameterGroupName: "${CP_RESOURCE_PREFIX}-db-param"`. Because `rds.force_ssl=1` stays enforced, keep `TP_DB_SSL_MODE=require` or `verify-full`.

### Simplified DNS and Gateway API

Simplified DNS (one Route 53 base domain, one ACM wildcard certificate, `dnsDomain == dnsTunnelDomain`) remains the recommended model. Since `tibco-cp-base` 1.19.0 the `hybrid-proxy` HTTPRoute renders `PathPrefix: /infra/tunnel` on its own and omits the catch-all `/` when the two domains are equal, so `hybrid-proxy` and `router-operator` can share the `*.${TP_BASE_DNS_DOMAIN}` hostname on the same Gateway. Note that the chart never consumed a `gatewayRoute.rules` value; remove any explicit rules left over from the 1.18 workaround.

### otel-collector and the Log Server

The workshop values files set `otel-collector.enabled: true` explicitly and configure `global.external.logserver`. If you rely on the chart default instead, be aware it is `false` in 1.20.0. Enable it only when an Elasticsearch or OpenSearch log server is reachable from the Control Plane namespace.

### Infra MCP Server and MCP Gateway RBAC

`dp-configure-namespace` 1.19.10 and later create RBAC for the Infra MCP Server and MCP Gateway capabilities (`rbac.infraMcp`, `rbac.mcpGateway`, `rbac.springboot`, all default `true`). Cluster-scoped diagnostics require `rbac.infraMcpClusterScoped=true`. TESSA, which consumes the Infra MCP Server, is only available on TIBCO Operated Control Plane (US region) in 1.20.0.

## Upgrade Path from v1.19.0

1. Back up Helm values, Kubernetes secrets (`session-keys`, `cporch-encryption-secret`), and Aurora PostgreSQL data. Record `helm history platform-base -n ${CP_INSTANCE_ID}-ns` so you can roll back.
2. Update the `tibco-platform` Helm repository.
3. Confirm `global.tibco.networkPolicy.createDeprecatedPolicies` is not in your values (removed in 1.19.0) and decide on `otel-collector.enabled` and `global.tibco.disabledInfraCapabilities`.
4. Upgrade `tibco-cp-base` to 1.20.0 (`helm upgrade ... --version 1.20.0`) or run `scripts/1.20.0/upgrade.sh` from `tp-helm-charts`.
5. Upgrade capability charts to 1.20.0 (`tibco-cp-bw`, `tibco-cp-flogo`, `tibco-cp-devhub`; `tibco-cp-hawk --version '1.20.*'`). Leave `tibco-cp-messaging` at 1.19.23.
6. Upgrade Data Plane infrastructure from the Control Plane UI (`dp-configure-namespace` 1.20.0, `dp-core-infrastructure` 1.20.3), then upgrade capabilities. The official matrix requires DP 1.20.0 and CP 1.20.0 for Flogo, BW5CE, BW6CE, and Developer Hub 1.20.0.
7. Validate with `scripts/verify-release.sh` from `tp-helm-charts` (`CHECK_RELEASE_FOLDER=control-plane`, `CHECK_RELEASE_VERSION=1.20.0`).

## Upgrade Path from v1.18.0

Direct 1.18.0 to 1.20.0 upgrades are not supported by the upgrade assistants (`scripts/1.19.0/upgrade.sh` requires `app_version` 1.18.0, `scripts/1.20.0/upgrade.sh` requires 1.19.0). Upgrade to 1.19.0 first:

1. Follow the [v1.19.0 upgrade path](./v1.19.0#upgrade-path-from-v1180).
2. Apply the v1.20.0 upgrade path above.

Alternatively use the sequential master script documented in `scripts/MASTER-UPGRADE-README.md` in `tp-helm-charts`.

## Known Issues to Review

New in 1.20.0:

- **PCP-23615:** after upgrading to 1.20.0, deleting a Data Plane's observability configuration fails. No workaround.
- **FLOGO-18866:** WebSocket application public endpoint URLs are shown with `https://`; replace with `wss://`.

Carried over and relevant to EKS, Traefik, and Gateway API users:

- **PCP-20148:** after the move to Jaeger v2 (1.19.0), traces recorded before the upgrade appear as red dots.
- **PCP-19820:** traces and application service metrics do not work with Traefik ingress in Control Tower Data Planes on TIBCO Operated Control Plane.
- **PCP-19687:** after a Control Plane upgrade, Integration Summary and Application Instance cards show wrong data for Data Planes that are still on the previous release. Upgrade the Data Plane.
- **PCP-17037 / PCP-9344 / BWCE-8521:** upgrading infrastructure without upgrading capabilities breaks Helm-managed deployments and hides endpoints and metrics. Always upgrade capabilities after infrastructure.
- **PCP-16403:** removing `use-forwarded-header: true` from the `dp-config-aws` nginx configmap breaks the BW Swagger UI (legacy nginx only).
- **MSGDP-199:** the EKS default `gp2` storage class does not support EMS shared logs; use EFS or provision without log sharing.
- **BWCE-11307:** Swagger tester is inaccessible for BW6 apps created on 1.17.0 and exposed through `traefik-gateway`; upgrade capability and app.
- **PLTDX-1459:** Control Plane and Developer Hub on the same cluster with Traefik and the same hostname return 404; use distinct FQDNs.

Closed in 1.20.0: PCP-23331 (CP service logs stopped writing to Elasticsearch after the 1.19.0 upgrade) and PCP-20976 (BW6 agent auto-switching with NGINX ingress and NetScaler).

Review the complete official list before production upgrades: [Official 1.20.0 Known Issues](https://docs.tibco.com/pub/platform-cp/1.20.0/doc/html/Release-Notes/known-issues.htm).
